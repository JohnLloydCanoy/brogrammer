# Anti-AI Slop UX Guidelines

Guidelines for engineering user experiences that prioritize human workflows, state resilience, deterministic interaction design, and domain-driven utility over generic AI tropes, conversational shortcuts, and fragile assumptions.

---

## 1. Banned UX Anti-Patterns

Strictly prohibit the following seven common AI-generated UX anti-patterns:

1. **The "Happy Path" Bias**:
   - *Banned*: Assuming everything functions under ideal network and data conditions. Designing exclusively for populated, perfect data feeds while completely ignoring empty states (when no records exist), loading skeletons, offline interruptions, network latency, and error recovery screens.
   - *Requirements*: Every view, widget, and component must explicitly engineer and test all five core UI states: **Empty** (constructive call to action), **Loading** (structural skeletons matching content geometry to prevent Cumulative Layout Shift), **Error** (clear diagnosis with retry mechanism), **Partial** (degraded, cached, or optimistic data), and **Populated** (scaled production data).

2. **The "Chatbot" Hammer**:
   - *Banned*: Treating natural language chat as a panacea for every interface challenge. Slapping an AI prompt input, floating copilot widget, or conversational text box onto a screen in lieu of building an intuitive direct-manipulation interface, structured forms, or purpose-built interactive tools.
   - *Requirements*: Design purpose-built workflows, specialized controls, multi-column tables, visual canvas editors, and structured forms tailored to the user's specific domain task. Reserve conversational chat exclusively for truly open-ended, multi-turn generative queries—never as a substitute for competent UX architecture.

3. **The Modal Maze**:
   - *Banned*: Defaulting to pop-up modal dialogs for every single interaction—such as editing account profiles, confirming trivial non-destructive actions, viewing detail records, or worse, spawning nested modals on top of existing modals.
   - *Requirements*: Use URL-backed page routing for distinct workflows and deep-linkable records; use inline editing for quick field updates; use slide-over/drawer panels for auxiliary inspection and contextual side workflows. Reserve modal dialogs strictly for high-consequence, irreversible destructive confirmations or focused, self-contained interrupts. Modal stacking/nesting is strictly forbidden.

4. **Lifeless Microcopy**:
   - *Banned*: Generating robotic, passive, vague, or placeholder button labels and error messages (e.g., "Get Started", "Learn More", "Submit", "Save", "An error occurred", "Something went wrong").
   - *Requirements*: Author explicit, action-oriented, contextual microcopy that explains the precise outcome of an interaction. Examples: "Start Analyzing Data", "Export 42 Records to CSV", "Save Billing Address", "Unable to save changes: Payment method expired. Update billing info". The user must understand exactly what will happen before and after every click.

5. **Amnesia Accessibility**:
   - *Banned*: Disregarding accessibility fundamentals—relying on non-semantic `<div>` and `<span>` elements as clickable buttons, stripping away keyboard focus rings, omitting `aria-label` attributes on icon buttons, ignoring tab ordering, and failing WCAG 2.1 AA contrast standards.
   - *Requirements*: Enforce native semantic HTML (`<button>`, `<main>`, `<nav>`, `<form>`, `<header>`, `<table>`). Maintain conspicuous, calibrated focus rings (`ring-2 ring-offset-2`) across all interactive targets. Support full keyboard navigation (Tab, Enter, Space, Escape, Arrow keys). Supply explicit ARIA labels for icon-only controls, leverage `aria-live` for dynamic state updates, and ensure all text meets or exceeds WCAG 2.1 AA standards.

6. **Statistical Navigation**:
   - *Banned*: Constructing navigation hierarchies out of boilerplate internet cliches ("Dashboard", "Analytics", "Settings", "Profile" dropdowns) without regard for the user's operational workflows, mental models, or frequency of access.
   - *Requirements*: Architect a user-centered Information Architecture (IA) derived directly from primary jobs-to-be-done and domain entities. Prioritize high-frequency tasks in the top-level structure, relegate administrative utilities to secondary tiers, maintain persistent breadcrumb trails, and provide unambiguous active-state indicators for current routes.

7. **The "Infinite Data" Dump**:
   - *Banned*: Rendering unbounded datasets or database queries directly onto the DOM without pagination, virtualization, or faceted filtering under the naive assumption that users will only ever create 5 to 10 sample items.
   - *Requirements*: Design for production scale from day one. Implement DOM virtualization for lists exceeding 100 items, provide server-side or client-side pagination with user-configurable page sizes, supply responsive multi-column sorting, debounced full-text search, multi-select batch operations, and defensive performance budgets.

## 2. State & Flow Architecture

Every screen, view, and data-bound component must be designed as a finite state machine covering all operational states:

```
                  ┌──────────────┐
                  │   Loading    │
                  └──────┬───────┘
                         │
         ┌───────────────┼───────────────┐
         ▼               ▼               ▼
  ┌──────────────┐┌──────────────┐┌──────────────┐
  │    Empty     ││  Populated   ││    Error     │
  └──────────────┘└──────┬───────┘└──────────────┘
                         │
                         ▼
                  ┌──────────────┐
                  │   Partial    │
                  └──────────────┘
```

### 1. Empty States
- **Constructive Guidance**: Never present an empty white canvas or a bare "No data found" label. Explain clearly why no data exists and what step is required to populate the view.
- **Primary Call to Action (CTA)**: Provide an immediate, prominent button or trigger (e.g., "Create Your First Project", "Connect a Data Source", "Import CSV").
- **Educational Context**: When appropriate, display a subtle visual schematic or contextual tips explaining how this view will function once populated.
- **Search & Filter Reset**: When an empty state results from an overly restrictive query or filter, provide a one-click "Clear All Filters" button alongside the message "No records match the selected filters".

### 2. Loading States & Skeleton Design
- **Geometry-Matched Skeletons**: Avoid generic spinning wheels for main content views. Use content-matched skeleton placeholders that mirror the exact layout, dimensions, and typography of the target data elements.
- **Zero Layout Shift (CLS)**: Skeleton containers must reserve the exact height and width of final elements to eliminate Cumulative Layout Shift upon data resolution.
- **Inline Spinners for Micro-Actions**: Restrict spinner animations to localized button states or inline badges during active mutation operations (e.g., saving a single form field or toggling a switch).
- **Graceful Delay**: For operations taking less than 150ms, avoid flashing skeleton screens to prevent jarring visual flicker; show immediate optimistic results or slight debounce.

### 3. Error States & Recovery
- **Deterministic Root Causes**: Never show generic errors like "An unexpected error occurred". Explain what failed (e.g., "Database connection timed out while querying transaction logs").
- **Preserve User Input**: In form validation or mutation failures, never wipe user-entered data or reset input fields. Keep all inputs intact and highlight specific failing fields.
- **Actionable Recovery Paths**: Every error view must provide an explicit remediation route—such as a "Retry Request" button, an "Open Network Settings" link, or an alternative offline fallback.
- **Field-Level Validation**: Pair inline field validation errors directly beneath the problematic input using `aria-describedby` and distinct high-contrast styling. Reserve toast notifications for transient system-level errors.

### 4. Partial & Optimistic States
- **Optimistic Updates**: Mutate the UI immediately upon user trigger (e.g., toggling a star, updating a status tag, archiving a record). If the network request fails, automatically roll back the UI to its prior state and display a clear error toast with an "Undo / Retry" option.
- **Stale-While-Revalidate (SWR)**: Render cached data instantly while refreshing records in the background, accompanied by a subtle, non-blocking timestamp or synchronization indicator (e.g., "Updated 2 minutes ago — refreshing...").
- **Degraded Network Handling**: If network connectivity drops, notify the user with a non-intrusive status banner indicating offline operation and queuing pending mutations.

### 5. Populated States
- **Visual Stability**: Maintain consistent grid alignments, column widths, and line-heights regardless of varying record counts.
- **Consistent Sorting & Hierarchy**: Default to the most logically relevant sort order (e.g., recent activity or severity) and ensure sorting states remain persistent across page navigation.

## 3. Interaction Design & Navigation

### Surface Selection: Routing vs. Drawers vs. Modals vs. Inline

Select the interaction container that corresponds directly to the complexity and disruption level of the task:

| Surface Type | When to Use | When Strictly Prohibited | Deep Linkable? |
| :--- | :--- | :--- | :--- |
| **Full Page (Route)** | Primary workflows, complex entity creation/editing, multi-step wizards, dedicated data exploration. | Simple field updates, minor confirmation alerts, auxiliary notes. | **Yes** (Unique URL) |
| **Slide-Over (Drawer)** | Contextual detail inspection, supplementary filters, reading side logs, quick creation while preserving main view context. | Critical multi-step workflows, high-consequence system alerts, mobile-narrow viewports without responsive fallback. | **Yes** (Query Param / Hash) |
| **Inline Editing** | Atomic value updates (renaming titles, toggling statuses, editing table cells, adjusting priority tags). | Complex nested forms requiring multi-field validation, bulk updates, multi-step operations. | **No** (Contextual) |
| **Modal Dialog** | High-consequence destructive confirmations, immediate authentication/session gates, critical blocking interrupts. | Standard forms, profile editing, viewing detail records, nested dialogs on top of existing modals. | **Optional** (Modal Route) |

### Modal Discipline
- **No Modal Stacking**: Never open a second modal dialog on top of an active modal. If a workflow inside a modal requires secondary confirmation, transition the contents of the modal or replace it with an inline prompt.
- **Click-Outside Safety**: Do not close modal dialogs on backdrop click if the modal contains uncommitted form input; accidental clicks must never destroy user progress. Require an explicit "Cancel" or "Discard Changes" action.
- **Escape Key Dismissal**: Always bind the `Escape` key to close non-destructive modals, returning focus cleanly to the invoking element.

### Information Architecture (IA) & Navigation Patterns
- **Jobs-to-be-Done Organization**: Structure primary navigation items around core user workflows (e.g., "Pipelines", "Deployments", "Audit Logs") rather than boilerplate generic buckets ("Dashboard", "General", "Misc").
- **Persistent Breadcrumbs**: In multi-tiered or parent-child data structures, provide clean, navigable breadcrumbs (`Projects / Marketing / Q4 Campaign`) allowing users to easily retrace steps.
- **Active State Fidelity**: Ensure the current active page or section is unambiguously highlighted in the navigation bar using high-contrast borders or background fills, alongside `aria-current="page"`.
- **Deep Linking Support**: Every significant entity, filter state, selected tab, and pagination index must sync with URL parameters to enable clean bookmarking, browser back-button navigation, and team sharing.

## 4. Action-Oriented Microcopy & Guidance

### Principles of Contextual Microcopy
- **Outcome-First Button Copy**: Every button label must state the specific verb and direct object of the resulting action.
  - *Bad*: "Submit", "Continue", "Save", "OK", "Next"
  - *Good*: "Save Billing Address", "Create Organization", "Deploy 3 Services", "Confirm & Charge $49"
- **Contextual Destruction Copy**: When performing irreversible operations, quantify the exact scope and impact in both the prompt and the action button.
  - *Bad*: "Are you sure? This action cannot be undone. [Delete]"
  - *Good*: "Delete 'Production Cluster 01'? This will immediately terminate 12 running containers and drop associated volumes. [Permanently Delete Cluster]"
- **Actionable Diagnostic Messages**: When an error or barrier occurs, state the precise cause and the immediate remediation step.
  - *Bad*: "Validation Error: Invalid input."
  - *Good*: "Invalid domain name: 'app..internal' contains consecutive dots. Remove the extra period to continue."

### Microcopy Anti-Pattern Catalog

| Anti-Pattern Copy | Why It Fails | Mandated Replacement |
| :--- | :--- | :--- |
| **"Get Started"** | Vague, generic marketing speak that fails to inform the user what setup is required. | **"Create Your First Repository"** / **"Connect Your Database"** |
| **"Learn More"** | Uninformative link text that destroys accessibility for screen readers scanning link lists. | **"Read the API Rate Limiting Documentation"** |
| **"Something went wrong"** | Blind panic; leaves the user powerless to diagnose or resolve the fault. | **"Failed to sync with GitHub: Authentication token expired. Re-authenticate account."** |
| **"Are you sure?"** | Trivialized confirmation prompt that users blindly click through. | **"Archive 15 Selected Invoices? They will be hidden from reports until unarchived."** |
| **"Click Here"** | Ambiguous interactive label that strips semantic purpose out of context. | **"Download Full Audit Log (CSV)"** |

## 5. Accessibility & Inclusivity Standards

### 1. Semantic HTML & Foundation
- **Native Elements First**: Use native `<button>` for clickable actions, `<a>` for navigational URL transitions, `<input>`/`<select>`/`<textarea>` for form controls, and `<main>`, `<nav>`, `<header>`, `<aside>` for landmark regions.
- **Div Prohibition**: Never use `<div onclick="...">` or `<span onclick="...">` for interactive triggers. If a customized composite control is necessary, apply explicit `role="button"`, `tabindex="0"`, and handle `Enter` and `Space` keyboard events.

### 2. Keyboard Navigation & Focus Management
- **Conspicuous Focus Rings**: Never suppress focus styles (`outline: none` without replacement is strictly forbidden). Use visible, high-contrast focus indicators:
  ```css
  /* Tailwind Standard */
  focus-visible:ring-2 focus-visible:ring-offset-2 focus-visible:ring-neutral-900 dark:focus-visible:ring-neutral-100
  ```
- **Logical Tab Order**: Tab indices must mirror the natural visual reading sequence of the interface. Avoid arbitrary positive `tabindex` values (`tabindex="1"`).
- **Modal & Drawer Focus Trapping**: When a modal dialog or slide-over opens, trap keyboard focus within the dialog container. Prevent tabbing into the obscured background page. Return focus to the original triggering button upon dismissal.
- **Escape Key Handling**: All overlays, dropdown menus, flyout popovers, and modal dialogs must close immediately upon pressing `Escape`.

### 3. ARIA & Screen Reader Support
- **Icon-Only Buttons**: Any button displaying only an SVG icon must include an explicit `aria-label` or visually hidden screen reader text:
  ```html
  <button type="button" aria-label="Close dialog">
    <CloseIcon aria-hidden="true" />
  </button>
  ```
- **Dynamic Announcements**: Announce dynamic state updates (toast alerts, background sync completion, filter tally updates) using appropriate `aria-live="polite"` or `aria-live="assertive"` regions.
- **Expandable Elements**: Any accordion, collapsible panel, or dropdown trigger must set `aria-expanded="true|false"` and `aria-controls="target-id"`.

### 4. Touch Targets & Visual Ergonomics
- **Minimum Target Size**: All interactive buttons, links, and form toggles must provide a minimum clickable target area of 44×44px (or 40×40px with appropriate spacing) to accommodate touch and motor-impaired navigation.
- **WCAG 2.1 AA Contrast**: All body text, button labels, and meaningful icons must maintain a minimum contrast ratio of 4.5:1 against their backgrounds (3:1 for large display headers).

## 6. Data Density & Scalability

### 1. Virtualization & DOM Pruning
- **Large Dataset Virtualization**: Any list, grid, or table expected to render more than 100 items must implement DOM virtualization (e.g., TanStack Virtual, `react-window`, or framework native virtual scrollers).
- **Memory Preservation**: Unrendered DOM nodes outside the current scroll viewport must be unmounted to maintain smooth 60fps scrolling and eliminate memory leaks.

### 2. Pagination & Infinite Scrolling Discipline
- **Explicit Pagination Default**: For administrative, auditing, and operational records, default to explicit pagination over infinite scrolling. Users must be able to locate specific pages, jump across ranges, and reference fixed URL states (`?page=3&limit=50`).
- **Configurable Page Sizing**: Allow users to select their preferred density (e.g., `25`, `50`, `100` items per page).
- **Infinite Scrolling Restrictions**: Infinite scrolling is only permitted in continuous activity feeds or media streams, and must always be paired with virtual scrolling and persistent URL scroll position restoration.

### 3. Search, Filtering & Batch Operations
- **Debounced Search**: Text search inputs querying server APIs must be debounced (300ms–500ms) to prevent network saturation.
- **Faceted Filters & Chips**: Display active filters as dismissible tags/chips above tables, showing the exact applied criteria with an immediate "Clear All" option.
- **Multi-Select Batch Controls**: Tables supporting batch operations must provide a master checkbox with indeterminate state (`indeterminate=true` when partial items selected), displaying an action bar indicating the count of selected items:
  ```
  [X] 14 items selected — [ Archive Selected ] [ Export to CSV ] [ Deselect All ]
  ```
- **Defensive Boundary Testing**: All views must be tested against edge-case data volumes: 0 records, 1 record, 10 records, 1,000 records, and records with excessively long character strings (enforce truncation with tooltips: `truncate max-w-xs`).

## 7. UX Audit Checklist

Before releasing any interface, verify complete compliance against this UX checklist:

- [ ] **Banned Anti-Pattern Verification**:
  - [ ] No "Happy Path" bias: Empty, loading skeletons, error with retry, and partial states exist and are verified.
  - [ ] No "Chatbot" hammer: Task is solved through purposeful interface controls, not a lazy conversational prompt box.
  - [ ] No "Modal Maze": No nested modals; standard workflows utilize routing, drawers, or inline editing; modals reserved for high-impact destructive confirmations.
  - [ ] No Lifeless Microcopy: Action-oriented, outcome-explicit labels used everywhere (no "Submit", "Get Started", "Learn More").
  - [ ] No Amnesia Accessibility: Native semantic elements used; full keyboard navigation and focus rings active; ARIA labels on icon buttons.
  - [ ] No Statistical Navigation: Information Architecture tailored to domain entities and user workflows; clear active route indicators and breadcrumbs.
  - [ ] No "Infinite Data" Dump: Virtualization or pagination implemented; multi-column sorting, search debouncing, and batch controls tested.
- [ ] **State & Flow Resilience**:
  - [ ] Empty state provides constructive explanation and a clear primary CTA.
  - [ ] Skeletons match target content geometry to eliminate Cumulative Layout Shift (CLS).
  - [ ] Error views provide root-cause diagnostics and an explicit retry/remediation button.
  - [ ] User input in forms is preserved during network or validation failures.
  - [ ] Optimistic updates include automatic rollback on error.
- [ ] **Navigation & Deep Linking**:
  - [ ] Deep links support entity IDs, tabs, search queries, filters, and pagination in the URL.
  - [ ] Drawers and slide-overs can be opened and shared via URL parameters where appropriate.
  - [ ] Escape key dismisses open menus, popovers, drawers, and non-destructive modals.
  - [ ] Modal backdrops with dirty forms require explicit confirmation before discarding edits.
- [ ] **Accessibility & Usability**:
  - [ ] All interactive elements pass WCAG 2.1 AA contrast requirements.
  - [ ] Keyboard focus ring is visible (`ring-2 ring-offset-2`) on all interactive targets.
  - [ ] Focus is trapped within open modal dialogs and returned to the trigger upon closing.
  - [ ] Icon-only buttons contain explicit `aria-label` attributes.
  - [ ] Dynamic updates are announced to assistive tech via `aria-live` regions.
  - [ ] Minimum interactive touch target size meets 44×44px standards.
- [ ] **Scalability & Density**:
  - [ ] Lists exceeding 100 items utilize DOM virtualization or pagination.
  - [ ] Data tables support multi-column sorting, debounced search, and batch selection.
  - [ ] Extreme text lengths are defensively truncated with accessible tooltips.
