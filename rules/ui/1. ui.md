# Anti-AI Slop UI Guidelines

Guidelines for building user interfaces that avoid generic AI-generated aesthetics, visual clichés, and decorative filler.

---

## 1. Visual Style, Color System & Elevation

### Gradients
- **Strictly No Gradients**: No dynamic gradients, linear gradients, radial gradients, or any gradient fills across backgrounds, cards, borders, text, or interactive controls unless explicitly asked by the developer.
- **Use Only Solid Colors**: All UI elements, surfaces, and accents must use flat, solid colors.

### Glow & Shadows
- **No Glow Effects**: No neon box shadows, ambient glow halos below buttons, or radiant colored lighting effects on any elements.
- **No Heavy Glassmorphism**: Do not default to heavy glassmorphism (`backdrop-blur` + low-opacity white borders) as a substitute for visual hierarchy.
- **Subtle Elevation**: Rely on clean 1px solid borders (`border-neutral-200` / `border-neutral-800` or calibrated design tokens) and flat bordered containers or subtle, natural, physically realistic neutral shadows.

### Color Palette & Brand Identity
- **Solid Colors Only**: Do not invent arbitrary uncalibrated gradients or color ramps.
- **Design Tokens & Project Specs**: Always refer to the colors established in the project documentation, design system, or defined tokens anywhere in the project.

### Dark Mode
- **No Glowing Pitch-Black**: Do not pair pitch-black backgrounds (`#000000`) with saturated neon borders or glowing orbs.
- **Layered Neutrals**: Use deep neutral grays (`#0f172a`, `#18181b`, `#111827`) with structured surface layering (`surface-0`, `surface-1`, `surface-2`). Keep border contrast subtle, clean, and calibrated (10% - 15% opacity or zinc/slate tokens).

## 2. Banned UI & Typography Clichés

Strictly avoid the following common AI-generated design clichés:

1. **The "Dark Mode" Cliché**:
   - *Banned*: Dark backgrounds paired with indigo-to-purple gradients, dot grids, and large, blurred glowing orbs behind text.
   - *Requirement*: Use solid, neutral dark surfaces with clean structural boundaries and clear contrast.

2. **The "Bento Box" Hero**:
   - *Banned*: A centered hero section featuring a pill-shaped "New" badge, a massive headline, a light-grey subtitle, two buttons (one primary, one outline), followed immediately by a masonry bento grid of features.
   - *Requirement*: Design an immediate, utility-first hero or workspace focused on user tasks, actual functionality, or real interactive previews above the fold.

3. **Card Overload (Card-ception)**:
   - *Banned*: Putting absolutely every piece of information inside a rounded card, often resulting in cards nested inside of other cards, all using the exact same corner radius.
   - *Requirement*: Use natural typographic rhythm, dividing lines, clean whitespace, and table or list layouts rather than wrapping every element in a rounded box.

4. **Whisper-Thin Typography**:
   - *Banned*: Massive, ultra-thin, low-opacity headlines that look sleek on screenshots but fail basic accessibility contrast ratios.
   - *Requirement*: Maintain strong, legible font weights (`font-medium`, `font-semibold`, `font-bold`), accessible contrast ratios (minimum 4.5:1), and deliberate semantic emphasis.

5. **The "Hello [Name]" Dashboard**:
   - *Banned*: Defaulting to generic dashboard layouts featuring a greeting, a summary card, four horizontal metric blocks, and one large chart, regardless of the product's actual function.
   - *Requirement*: Tailor dashboard architecture strictly to the domain problem—prioritizing actionable work items, operational filters, data tables, and high-priority alerts over generic vanity metrics.

6. **Flat Visual Hierarchy**:
   - *Banned*: Perfectly symmetrical, repetitive sections (e.g., icon, title, two lines of text) where every element carries the exact same visual weight, leaving the user with no clear focal point.
   - *Requirement*: Establish clear primary, secondary, and tertiary focal points through deliberate sizing, weight, and visual contrast.

7. **The "Colored Square" Iconography**:
   - *Banned*: Relying heavily on generic, mono-line icons placed perfectly inside softly rounded, pastel-colored squares next to every feature description.
   - *Requirement*: Use meaningful, context-specific iconography without decorative square containers, or rely on clear typographic headings alone.

8. **The Inter/Roboto Monoculture**:
   - *Banned*: Defaulting exclusively to system sans-serifs (like Inter, Roboto, or SF Pro) for everything, stripping away any brand personality or stylistic hierarchy.
   - *Requirement*: Choose intentional typographic pairings aligned with project branding and distinct stylistic hierarchy.

9. **The Gradient Hero H1**:
   - *Banned*: Slapping `bg-clip-text text-transparent bg-gradient-to-r` (usually purple-to-pink or blue-to-teal) on every single landing page headline to make it look "tech-forward".
   - *Requirement*: Use solid, high-contrast headline colors with purposeful weight and typographic character.

10. **The Muted Gray Unreadability**:
    - *Banned*: Defaulting secondary or body text to `text-gray-500` on white backgrounds (or `text-gray-400` in dark mode), aggressively failing basic WCAG contrast accessibility checks.
    - *Requirement*: Ensure all body and secondary text strictly passes WCAG AA contrast standards (minimum 4.5:1 ratio).

11. **Extreme Size Jumps**:
    - *Banned*: Pairing a massive `text-7xl` or `text-8xl` main headline directly next to a tiny `text-sm` body paragraph, completely ignoring proportional, mathematical type scales.
    - *Requirement*: Use balanced, step-wise typographic scales (e.g., Major Second, Minor Third, Perfect Fourth) for harmonious heading-to-body size transitions.

12. **The Spaced-Out Eyebrow**:
    - *Banned*: Overusing `uppercase tracking-widest text-xs font-semibold` for every single tag or category label above a main title.
    - *Requirement*: Use natural case, subtle tags, or standard typographic hierarchy without defaulting to ubiquitous micro-spaced uppercase eyebrow text everywhere.

13. **The Random Italicized Serif**:
    - *Banned*: Forcing one specific word in a sleek sans-serif headline to be a serif italic in an attempt to artificially simulate an "editorial" or "premium" feel.
    - *Requirement*: Maintain consistent typographic style within headlines; convey emphasis through natural phrasing, position, weight, or color rather than random font-family switching.

14. **Infinite Line Lengths**:
    - *Banned*: Generating text blocks without applying `max-w-prose` or `text-wrap: balance`, resulting in paragraphs that stretch awkwardly across the entire width of an ultrawide monitor with orphaned words dangling on the last line.
    - *Requirement*: Enforce readable line lengths (45–75 characters per line, `max-w-prose`, `max-w-xl`/`max-w-2xl`) and balanced headline wrapping (`text-wrap: balance`).

## 3. Typography, Copywriting & Readability

### Typographic Hierarchy & Scale
- **Intentional Pairings**: Avoid defaulting to the Inter/Roboto monoculture. Choose intentional font pairings that align with project branding and establish clear visual hierarchy between display titles and functional UI elements.
- **Harmonious Mathematical Scales**: Avoid extreme size jumps (such as jumping from `text-7xl` directly to `text-sm`). Employ balanced, step-wise typographic scales (e.g., Major Second [1.125], Minor Third [1.2], or Perfect Fourth [1.333]) to create smooth, proportional heading-to-body transitions.
- **Consistent Headline Styling**: Do not mix font families arbitrarily (e.g., forcing a random serif italic word inside a sans-serif headline). Maintain consistent font styling throughout headlines; express emphasis using semantic phrasing, natural visual hierarchy, weight, or color.
- **Solid Headline Colors**: Never use gradient text fills (`bg-clip-text text-transparent bg-gradient-to-r`). Keep headlines in solid, high-contrast colors with deliberate weight and typographic character.

### Readability, Line Length & Contrast
- **WCAG AA Contrast Standards**: Strictly avoid unreadable muted grays (`text-gray-500` on white surfaces or `text-gray-400` in dark mode). All body text and secondary copy must strictly meet or exceed WCAG AA contrast standards (minimum 4.5:1 contrast ratio against the background).
- **Optimal Line Lengths & Wrapping**: Never leave text blocks unconstrained across wide viewports. Enforce optimal reading widths (45–75 characters per line, `max-w-prose`, `max-w-xl`, or `max-w-2xl`) and utilize `text-wrap: balance` on headlines to eliminate orphaned words.
- **Sizing & Legibility**: Maintain readable body text sizing (`14px` or `16px`).
- **Tabular Data**: Use tabular numbers (`font-mono` or `font-variant-numeric: tabular-nums`) for currency, timestamps, and metrics.

### Labels, Eyebrows & Badges
- **Natural Case & Hierarchy**: Avoid relying on ubiquitous spaced-out uppercase tags (`uppercase tracking-widest text-xs font-semibold`) above every headline. Use natural case, subtle tags, or standard typographic hierarchy.
- **No Emojis**: Absolutely no use of emojis in text, headings, buttons, or labels (e.g., `✨`, `🚀`, `🔥`, `💡`).
- **No Feature Badges**: Do not use pill-shaped "New", "Beta", or "Feature" badges and tags.
- **Functional Status Indicators Only**: Use clean, functional text labels and reserve badges strictly for functional status indicators (e.g., "Active", "Pending", "Failed") when necessary.

### Copywriting
- **No Marketing Buzzwords**: Avoid vague filler ("Supercharge your workflow", "Seamlessly integrate your disparate systems", "Unleash the power of...").
- **Plain, Actionable Language**: State clearly what the feature does, what input is required, and what the result is (e.g., "Filter audit logs by date range, user ID, or event severity").
- **Realistic Mock Data**: Never use Latin filler (`Lorem ipsum`) or meaningless labels (`Item 1`, `Item 2`). Use realistic domain data.

## 4. Iconography & Assets

### Asset Usage over Placeholders
- **Asset Folder Reference**: Always refer to an asset folder or related files for that on each development rather than placeholders (e.g., avoid `via.placeholder.com`, Unsplash stock links, or empty placeholder boxes).
- **Project Assets First**: Verify existing local project icons, logos, and images before introducing external or arbitrary assets.

### Purposeful Icons
- Use icons only when they assist scanning or signify a concrete interactive action (e.g., search, chevron, external link, download, trash).
- Avoid generic icon groupings (the "Rocket, Zap, Shield, Globe" quartet).
- Do not place floating 3D shapes, abstract isometric illustrations, or meaningless geometry in the background.

---

## 5. Layout, Density & Interactions

### Layout Utility & Density
- Design directly for utility: prioritize workflows, actionable filters, lists, tables, and settings over marketing whitespace.
- Optimize information density appropriate for the domain (e.g., compact tables for data-dense tools).
- Avoid unconstrained horizontal stretching across widescreen layouts.

### Animations
- Keep transitions subtle, fast, and functional (`duration-150` to `duration-200`, ease-out).
- Do not add gratuitous hover micro-animations (e.g., cards scaling to `scale-105` with delayed bounce transitions, pulsing buttons).
- Ensure motion respects `prefers-reduced-motion`.

### Component States
Every interactive component must clearly handle:
1. **Default**: Solid surfaces and clear boundaries.
2. **Hover**: Observable but subtle shift in solid background or border color.
3. **Focus**: Visible keyboard focus ring (`ring-2 ring-offset-2`).
4. **Active/Pressed**: Tactile feedback.
5. **Disabled**: Reduced opacity (`opacity-50`) with `pointer-events-none` or `cursor-not-allowed`.
6. **Empty & Error States**: Explicit fallback messaging explaining what is missing and how to resolve it.

## 6. Audit Checklist

Before finalizing any UI implementation, verify:
- [ ] **Gradients**: No dynamic or linear/radial gradients used anywhere unless explicitly requested by the developer. Solid colors only.
- [ ] **Glow & Shadows**: No neon box shadows, ambient glows under buttons, or radiant blobs. No heavy glassmorphism crutches.
- [ ] **Color Palette**: All colors adhere to project documentation, design system, or established theme tokens.
- [ ] **Emojis & Badges**: Zero emojis in text/headings/buttons/labels. No pill-shaped "New", "Beta", or "Feature" badges.
- [ ] **Banned Clichés**:
  - [ ] No "Dark Mode" glowing orbs or dot grids.
  - [ ] No "Bento Box" hero templates.
  - [ ] No "Card-ception" (nested rounded cards with identical radii).
  - [ ] No "Whisper-Thin" low-contrast typography.
  - [ ] No generic "Hello [Name]" dashboard layouts.
  - [ ] No flat, unprioritized visual hierarchy.
  - [ ] No "Colored Square" icon backplates.
  - [ ] No "Inter/Roboto Monoculture" (generic system sans-serif monoculture lacking brand personality).
  - [ ] No "Gradient Hero H1" (`bg-clip-text text-transparent bg-gradient-to-r` headlines).
  - [ ] No "Muted Gray Unreadability" (`text-gray-500` / `text-gray-400` failing WCAG AA).
  - [ ] No "Extreme Size Jumps" (disproportionate headline-to-body scale jumps).
  - [ ] No "Spaced-Out Eyebrow" (`uppercase tracking-widest text-xs font-semibold` tag spam).
  - [ ] No "Random Italicized Serif" (gimmicky one-word font-family shifts in headlines).
  - [ ] No "Infinite Line Lengths" (unbounded paragraphs lacking `max-w-prose` or `text-wrap: balance`).
- [ ] **Asset Usage**: Real project assets referenced from the asset folder/files instead of placeholders.
- [ ] **Typography & Copy**:
  - [ ] WCAG AA compliant contrast (minimum 4.5:1 ratio for body and secondary text).
  - [ ] Intentional font pairings aligned with branding; no default sans monoculture.
  - [ ] Proportional, step-wise type scales with smooth heading-to-body transitions.
  - [ ] Solid, high-contrast headlines without text gradient masks or random italicized serif words.
  - [ ] Constrained line lengths (45–75 chars / `max-w-prose`) and balanced headline wrapping (`text-wrap: balance`).
  - [ ] Natural case labels/tags instead of ubiquitous spaced-out uppercase eyebrows.
  - [ ] Tabular numbers for metrics and dates.
  - [ ] Plain, factual copy without marketing buzzwords.
- [ ] **Interactive States**: Default, hover, keyboard focus, active, disabled, and empty/error states are implemented.
