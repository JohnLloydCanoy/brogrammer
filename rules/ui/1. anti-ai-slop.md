# Anti-AI Slop UI Guidelines

Guidelines for building user interfaces that avoid generic AI-generated aesthetics, visual clichés, and decorative filler.

---

## 1. Visual Style & Styling Clichés

### Gradients and Glowing Elements
- **Do not** use multi-stop violet/indigo/pink/fuchsia linear gradients on text, card borders, or backgrounds.
- **Do not** use neon box shadows, ambient glow halos behind buttons, or floating radiant colored blobs.
- **Do not** default to heavy glassmorphism (`backdrop-blur` + low-opacity white borders) as a substitute for visual hierarchy.
- **Do**:
  - Use solid, high-contrast surface colors with clean 1px borders (`border-neutral-200` / `border-neutral-800`).
  - Restrict accent colors to a single, intentional brand or semantic hue.
  - Rely on elevation through subtle, natural shadows or flat bordered containers.

### Dark Mode
- **Do not** use pitch-black backgrounds (`#000000`) paired with saturated neon borders.
- **Do**:
  - Use deep neutral grays (`#0f172a`, `#18181b`, `#111827`) with layered elevations (`surface-0`, `surface-1`, `surface-2`).
  - Keep border contrast subtle and readable (`10% - 15%` white opacity or calibrated slate/zinc tokens).

---

## 2. Iconography & Decor

### Sparkles and Cliché Icons
- **Do not** prefix headings, feature badges, or primary buttons with sparkles (`✨`, `Sparkles` icon) unless the feature is explicitly a non-deterministic generative action.
- **Do not** use the generic "Rocket, Zap, Shield, Globe" quartet for feature grids.
- **Do not** place floating 3D shapes, abstract isometric illustrations, or meaningless geometry in the background.
- **Do**:
  - Use icons only when they assist scanning or signify a concrete interactive action (e.g., search, chevron, external link, trash).
  - Prefer clean typographic labels over decorative icon soup.

---

## 3. Layout & Structure

### The Generic "SaaS Landing Page" Pattern
- **Do not** default every application or page to the standard template:
  1. Massive centered hero with two pill buttons and glowing background.
  2. Logo cloud of fake companies.
  3. 3-column card grid with generic icons.
  4. Centered testimonial carousel.
  5. Giant CTA block with a gradient background.
- **Do**:
  - Design directly for the utility of the screen: data density, workflows, actionable filters, lists, tables, and settings.
  - Prioritize immediate utility over marketing whitespace. Place actual functionality or real preview data above the fold.

### Whitespace & Density
- **Do not** pad containers with excessive whitespace to make low-density pages look full.
- **Do**:
  - Optimize for information density suitable for the application's domain (e.g., compact tables for dashboards, readable line lengths for documentation).

---

## 4. Typography & Copywriting

### Copywriting Clichés
- **Do not** generate vague marketing buzzwords:
  - "Supercharge your workflow with next-gen AI-powered synergy"
  - "Seamlessly integrate your disparate systems into one unified hub"
  - "Empowering teams to build the future faster"
  - "Unleash the power of..."
- **Do**:
  - Write plain, factual, and actionable copy:
    - State what the feature does, what input is required, and what the result is.
    - Example: "Filter audit logs by date range, user ID, or event severity."
  - Avoid Latin filler (`Lorem ipsum`) and placeholder text like `Item 1`, `Item 2`. Use realistic domain data.

### Typographic Hierarchy
- **Do not** use ultra-thin font weights (`font-thin`, `font-extralight`) on colored backgrounds.
- **Do**:
  - Maintain legible body text sizing (`14px` or `16px`) with high contrast ratios (minimum 4.5:1 against the background).
  - Use tabular numbers (`font-mono` or `font-variant-numeric: tabular-nums`) for currency, timestamps, and metrics.

---

## 5. Components & Interaction

### Animations
- **Do not** add gratuitous hover micro-animations (e.g., cards scaling to `scale-105` with a delayed bounce transition, pulsing buttons).
- **Do**:
  - Keep transitions subtle, fast, and functional (`duration-150` to `duration-200`, ease-out).
  - Ensure motion respects `prefers-reduced-motion`.

### State Handling
- Every interactive component must specify:
  1. **Default**: Clear boundaries and contrast.
  2. **Hover**: Observable but subtle shift in background or border color.
  3. **Focus**: Visible keyboard focus ring (`ring-2 ring-offset-2`).
  4. **Active/Pressed**: Slight tactile feedback.
  5. **Disabled**: Reduced opacity (`opacity-50`) with `pointer-events-none` or `cursor-not-allowed`.
  6. **Empty & Error States**: Explicit fallback messaging explaining what is missing and how to resolve it.

---

## 6. Audit Checklist

Before finalizing any UI implementation, verify:
- [ ] No gradient text or glowing multi-colored card borders.
- [ ] No sparkles (`✨`) on non-generative elements.
- [ ] No marketing filler or buzzword headings.
- [ ] Data tables and lists use realistic, domain-specific mock data.
- [ ] Contrast meets WCAG AA standards.
- [ ] Visible keyboard focus states exist on all interactive controls.
- [ ] Empty, error, and loading states are defined with functional copy.
